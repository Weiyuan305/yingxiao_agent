# 留学营销智能体调研

日期：2026-05-29  
目录：`/Users/weiyuan/personal/study-abroad-marketing-agent`

## 一句话结论

可以做，而且已有很多相近项目可参考；但建议不要直接 fork 一个大而全的营销平台。你的场景核心不是“全平台自动发”，而是“每天发现留学相关新消息，核验后生成可发布草稿”。所以第一版应做成一个垂直内容工作台：采集、筛选、摘要、事实核验、生成小红书/抖音草稿、人工发布。

## 有没有人做过

有，主要分为几类：

1. AI 内容营销一体化平台  
   代表：AiToEarn、TryPost、Socialkin、Regent、Make0 等。它们覆盖内容生成、排期、发布、互动或变现，但不是专门为留学信息监控和中文平台审核设计。

2. 社媒发布自动化工具  
   代表：social-auto-upload、xhs_ai_publisher、Autoxhs。它们更接近“上传/发布”执行层，适合后期复用，但小红书和抖音发布链路容易遇到登录态、验证码、风控和平台规则问题。

3. 内容生成与短视频工具  
   代表：OpenShorts、ViMax、ClipForge、LangChain social-media-agent。它们可以复用脚本生成、视频分镜、内容改写、人审流程等思路，但缺少留学垂直数据源和中文平台格式化。

## 最有价值的可复用项目

| 项目 | 可复用点 | 适配度 | 主要风险 |
| --- | --- | --- | --- |
| yikart/AiToEarn | 多平台内容营销、发布、Agent、Docker 部署 | 高，适合作为产品参考或二次调研对象 | 目标太大，直接 fork 容易背上复杂业务；需要核查真实可运行程度 |

## 数据源建议

优先级从高到低：

1. 官方信息源  
   美国、英国、加拿大、澳洲、新西兰等移民局、签证中心、教育部门、学校官网、招生办新闻、奖学金页面。优点是可信，适合做“政策/申请提醒”内容。

2. 新闻 API / RSS  
   News API、GDELT、Google News RSS、主流媒体教育频道、学校 RSS。适合做每天的新闻候选池。

3. X.com  
   用 X API recent search 监控关键词、官方账号、学校账号、留学顾问/KOL 账号。X 官方文档说明 recent search 可查最近 7 天，适合每日任务。

4. RSSHub  
   可补齐很多没有官方 RSS 的站点。它支持大量社媒和新闻路由，包括微博、B站、小红书用户路由、TikTok 用户路由等；但需要把它当作辅助源，不要作为唯一事实来源。

5. 小红书  
   不建议第一版自动抓全站搜索。可以先做“人工添加小红书链接/账号观察列表/关键词笔记备忘”，再尝试合规 API 或受控 RPA。小红书官方开放能力更偏广告、电商、商家、蒲公英、数据洞察，并不是通用内容搜索和发布 API。

## 推荐产品形态

网站后台，不是公开营销官网。第一屏就是运营工作台：

- 今日候选消息：按国家、签证、院校、申请季、就业、奖学金分类。
- 事实卡片：原文链接、发布时间、来源可信度、摘要、关键变化、风险提示。
- 内容草稿：一键生成小红书笔记、抖音口播稿、标题、标签、封面文字。
- 审核队列：人工改稿、确认事实、标记“可发/待核验/不要发”。
- 发布包：复制文案、下载封面图、导出视频脚本和素材清单。

## 推荐技术路线

### 路线 A：自建垂直 MVP（推荐）

Next.js + Postgres/Supabase + 队列/cron + LangGraph 或简单任务流水线。

优点：
- 能完全围绕留学业务设计。
- 不被大项目复杂度拖住。
- 第一版就能把事实核验和人工审核做扎实。

缺点：
- 发布执行层要后续接入。
- 需要自己做采集器和草稿管理。

### 路线 B：fork AiToEarn 改造成留学版

优点：
- 已有多平台营销和发布概念。
- MIT 许可证，理论上可商用改造。

缺点：
- 业务面太宽，可能比重写 MVP 更慢。
- 需要实际 clone、跑通、看代码质量后才能决定。

### 路线 C：n8n/Make + 表格 + AI 先跑流程

优点：
- 最快验证需求。
- 适合先验证“每天能不能产出 3-5 条有价值选题”。

缺点：
- 后续做成产品时需要迁移。
- 审核、权限、素材管理和复用能力弱。

## 我的建议

先走路线 A，同时把 AiToEarn、LangChain social-media-agent、xhs_ai_publisher、social-auto-upload 作为参考项目。MVP 不要做自动发布，只做高质量草稿和人工发布包。

原因：

- 留学内容错误成本高，签证和政策信息必须人工确认。
- 小红书/抖音自动发布容易风控；你当前也说“手动发布”，这正好降低复杂度。
- 真正的壁垒是垂直数据源、选题判断、事实核验和平台化表达，不是按钮式发帖。

## MVP 里程碑

第 1 周：
- 建数据源配置：关键词、国家、学校、官方站点、X 账号、RSS。
- 每天抓取并去重，生成“今日留学情报”。
- 人工添加链接入口。

第 2 周：
- 做留学相关性评分和分类。
- 做事实卡片：原文、摘要、影响人群、可信度、待核验点。

第 3 周：
- 做小红书文案生成：标题、正文、标签、封面文案、评论区引导。
- 做抖音脚本生成：30 秒、60 秒两个版本，口播稿、字幕、分镜、B-roll 建议。

第 4 周：
- 做审核队列和发布包导出。
- 每天跑一次自动任务，人工选 3-5 条发布。

## 关键风险

1. 平台规则  
   X 有官方 API；抖音发布能力需要申请权限，并强调用户自主发布。小红书通用内容 API 不明确，RPA 自动化发布有风控风险。

2. 内容事实  
   留学、签证、移民政策不能只靠模型摘要。需要保存来源链接、发布时间、原文摘录、人工确认状态。

3. 版权  
   新闻源只做摘要、引用短句和链接，不复制全文。视频素材和图片要使用可授权素材或自生成素材。

4. 平台内容合规  
   小红书和抖音不适合夸大“保录取”“保证签证”“低成本移民”等营销话术。文案生成要内置禁用词和风险提示。

## 下一步建议

下一步应该先确认 MVP 的业务边界：

- 第一版主要服务哪个国家或地区：美国、英国、加拿大、澳洲，还是多国？
- 内容形态更重小红书图文，还是抖音短视频口播？
- 每天目标产出多少条：3 条精品，还是 10-20 条候选？
- 是否需要团队协作和客户/账号区分？

确认这些之后，再写正式产品规格和开始搭网站。
